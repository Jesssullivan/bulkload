# Migration contract

## State matrix

| State | Observe | Move | Verify | Default |
|---|---|---|---|---|
| Clean Git refs/objects | all names under `refs/` with object and symbolic target, HEAD, branch, upstream, remote, bounded recovery-only reflog/pseudo-ref roots, reachable-object closure, and full object-integrity check | fetch/push or verified bundle; temporary exact-OID refs retain recovery roots | exact source non-remote refs and recovery anchors, symbolic targets, reachable ancestry, and uncorrupted object storage; report destination-only refs and block extra replacement refs | reconstruct |
| Linked worktrees | path, common dir, branch/detached, HEAD, lock/prune; sibling dirt requires a separate capture per worktree | recreate from reviewed ref | host-local inventory plus exact active lane | never raw-copy |
| Modified tracked bytes | exact four-octal mode, size, SHA-256, status | accepted content plan | fresh file and status catalog with exact mode | eligible if unstaged |
| Safe untracked bytes | mode, size, SHA-256, status | accepted content plan | fresh file and status catalog | eligible |
| Staged/conflicted/deleted state | index/worktree code and path | separate recovery design | exact index stages and bytes | block v1 |
| Ignored/generated bytes | bounded inventory | regenerate | destination-native checks | exclude |
| Agent transcripts | path, mode, size, prefix/hash, open/closed | destination-absent or proof-bound superset plan | JSONL validity, mode, exact hash or record-boundary prefix | opt in |
| Agent indexes/caches | metadata only | regenerate | destination application rebuild | exclude |
| Codex auth | existence, owner/mode, exact digest/size/identity; never values | policy v7 attended atomic replace with external backup and journal | fresh offline capture, rollback evidence, then a fresh attended provider turn | opt in; typed auth install |
| Codex SQLite families | effective authority, complete family inventory, structured schema/migration/table/path facts, absent WAL/SHM/journal sidecars | retain immutable v4/v5 opening/close/action evidence and exact v6 request/capacity evidence as validator-only inputs; preserve destination exact during auth; no composer/reservation/publish/install | v7 internal read-only oracle over fixtures built separately without invoking the oracle; later complete-chain final verification, picker, and resume acceptance | opt in; diagnostic oracle only |

## Required proofs

For an active Git lane, require all of:

1. exact logical lane selection;
2. exact branch and HEAD;
3. exact upstream and live remote head;
4. clean or exactly cataloged dirt;
5. source pass A equals source pass B;
6. verified commit signature when the repository requires signing;
7. no ineligible state used as an input; and
8. fresh destination verification after transfer.

For a Codex same-UUID prefix decision, keep both writers quiesced through two
proof passes. After all required proofs, compile an immutable close request
that binds their exact capture IDs and proof digests. Only then capture fresh
closing A/B wrappers for both roots against that request. Every opening, proof,
and closing snapshot capture ID must be distinct; the closing catalog/custody
bodies must equal the opening bodies; and the plan must bind the prefix
request, proofs, close request, and wrapper digests. Session snapshots remain
schema v2; the close request and close-capture wrapper use their own v1
schemas. A future copier must still enforce the exact source and
`destination_before` hashes and sizes immediately before replacement.

Filename classification is deliberately conservative but finite. Before plan
acceptance, inspect every operation and run the operator-approved redacted
secret scanner when available. Generic repository-file eligibility never
promotes a credential or decrypted secret. A provider-specific auth adapter is
the only permitted copy path and must keep values out of evidence.

For policy v7 auth install, prefer source `["auth"]` and destination
`["auth","sqlite"]`. Source and destination both selecting auth plus SQLite is
also accepted, but source SQLite is never consumed. The destination capture is
the selected-state authority: every destination family must be preserved
exactly, the plan must report `sqlite_union_ready=false`, and every mutating
receipt's SQLite mutation count must remain zero.

Each private capture or operation requires a short-lived, digest-accepted
quiescence attestation bound to its exact purpose, roots, selected classes,
host authority, Codex version, accepted digests, and output. This is an
operator procedural fence with `provider_writer_proof=false`. The accompanying
advisory `flock` excludes only cooperating Bulkload processes and is not proof
that Codex is stopped. The supported launcher must enter Python with `-I -S`
before startup hooks. The canonical private policy and Bulkload
application-source closure must then be pinned before command imports, bound
into the compatibility and install plans, and revalidated through every
mutation/publication boundary. This does not bind the interpreter or
standard-library closure.

The v5 SQLite close request binds the complete accepted v4 opening, one fresh
writer-stop epoch, both private opening stable projections, and both session
opening custody/catalog projections. Fresh source/destination private and
session A/B closes must use globally distinct capture identities, share that
epoch, remain stable within each role, and exactly equal their opening
projections. The close compiler must recompute the v4 opening from its original
inputs before and after publication. The offline action plan binds that proof
and all close evidence, but independently reopens the same complete v4 input
set before compilation and after publication rather than trusting the close's
revalidation claim. It then records complete expected output counts and
semantic digests plus a descriptive create-only operation graph.
Current readiness is limited to families whose schema and migration state are
already exact. Registered-prefix skew emits
`pinned-migration-adapter-not-implemented`; v5 does not execute an adapter.
`descriptive_action_complete=true` records that semantic planning closed, while
`ready_for_offline_compose=false` remains invariant. The v5 plan contains no raw
values, output/workspace authority, capacity proof, composer runtime, or
receipt contract and authorizes no composer or live-root mutation.

The v6 compose request accepts only the exact repaired v5 producer policy and
runtime closure. It separately binds the then-active v6 consumer runtime, an
existing descriptor-pinned `0700` workspace parent, an absent
action-digest-derived final leaf, an empty randomized-staging namespace, every
opening/closing evidence parent, and all recorded live private/session roots.
Lexical and descriptor lineage checks reject aliases and both ancestry
directions. A deterministic checked-integer capacity requirement is part of
the request; caller-available `f_bavail * f_frsize` and `f_favail` enter a
separate 300-second observation. Neither artifact reserves bytes/inodes or
binds a composer runtime. Both keep compose, publish, install, apply,
provider-writer proof, and readiness false.

The immutable
[v6 full application-source inventory](codex-private-runtime-inventory.v6.json)
binds all 16 Bulkload Python source paths and digests from signed source commit
`7bd06a05f7a4710e42fac6be08b477b801493c95`. Its canonical aggregate must remain
`5adfc213cf657d24d3bd8de3ab6b5f9e3d1bf14627045c8526d0b32241f460f5`;
the v6 policy remains byte-frozen.

Policy v7 retains the exact v6 policy/application/request validators but registers
neither request nor capacity producer command. Its internal verifier oracle
opens an already hand-built owner-private bundle read-only, separately observes
schema, migrations, typed rows, foreign keys, and manifest/receipt bindings,
and emits only the strict
`dev.tinyland.bulkload.codex-private-sqlite-verifier-oracle-report.v7`
diagnostic schema. The oracle has no CLI, writer, publisher, final-receipt, or
live-root authority. A zero-failure report still keeps bundle-sealed,
complete-input-recomputation, final-verification, installation, provider
acceptance, and cutover claims false.

Worktree counts and basenames may differ legitimately. A worktree is a
host-local projection of Git and working state, not a portable identity.

## Stop conditions

Stop before application when any of these is true:

- source pass A and B differ;
- either capture is incomplete;
- a source or destination writer cannot be quiesced enough to get stable passes;
- a private-state attestation is expired, mismatched, reused for an independent
  proof, or presented as provider-writer proof;
- any selected SQLite authority contains a live `-wal`, `-shm`, or `-journal`
  sidecar;
- the current private policy/application-source closure differs from the authority bound
  into an accepted plan;
- a v5 close artifact wraps prior evidence instead of recapturing the live
  root, does not share the exact writer-stop epoch, reuses an identity, drifts
  from its role's opening projection, or lacks all required private/session
  source/destination A/B passes;
- a SQLite action plan fails to recompute the complete v4 opening, requires an
  adapter or other schema-skew execution, lacks exact expected output
  counts/digests, or is presented as composer, publisher, installer, session,
  or cutover authority;
- a v6 request is not backed by the exact repaired v5 producer closure, uses a
  non-v6 consumer runtime, omits any v4-to-v5 recomputation input, proposes a
  workspace that is not an existing same-UID exact-`0700` owner directory,
  carries any private evidence or protected namespace owned by another UID,
  overlaps a protected namespace, finds an occupied final/staging name,
  overflows its capacity derivation, or is presented as compose/write
  authority;
- a capacity observation is expired, bound to another request/host/workspace/
  runtime, uses privileged free blocks instead of caller-available capacity,
  is insufficient, or is presented as reservation or future-write proof;
- a v7 oracle report has an unknown key, is bound to a non-active verifier
  source, accepts an artifact outside the pinned owner-private bundle, observes
  schema/row/migration/edge drift, promotes any diagnostic observation into a
  final/public claim, or is presented as a sealed-bundle or independent final
  verification receipt;
- a private install would consume source SQLite, mutate destination SQLite,
  compose/install a SQLite family, or combine auth and SQLite apply;
- source and destination Git heads diverge;
- the destination has dirt absent from the source;
- a path is staged, conflicted, deleted, special, absolute, traverses a symlink,
  or is itself a dirty or untracked symlink mutation;
- a sensitive path requires a working-byte operation;
- Git LFS or another content filter, local/external attribute authority,
  legacy grafts, shallow or partial/promisor history, submodules, or object
  alternates lack a separate reviewed plan;
- any source non-remote ref is absent, has a different object or symbolic
  target, or lacks its reachable object closure on the destination;
- any source recovery-only reflog or pseudo-ref OID lacks an exact destination
  HEAD, local-ref, or recovery-root anchor (ancestor-only presence is not a v1
  proof; create a temporary retention ref and recapture);
- an active rebase, apply-mailbox, sequencer, bisect, merge, cherry-pick, or
  revert administration state exists; v1 types and blocks it instead of
  pretending that preserved object IDs can resume the operation;
- a destination replacement has no external backup location;
- the exact plan digest was not accepted;
- credential values would enter evidence, a provider-specific auth/SQLite plan
  is absent, or activation, deployment, or terminal-session authority would be
  required; or
- the transport cannot preserve the promised file class.

## Evidence bundle

Retain source A, source B, destination-before, plan, apply receipt or transport
log, destination-after, verification, tool commit, host/time metadata,
exclusions, and operator decisions. Manifests contain hashes and paths, not file
contents. Store the bundle with owner-only permissions because filenames and
repository topology may still be sensitive.

## Product boundary

Bulkload v1 proves integrity and scoped parity, not authenticity, global
filesystem atomicity, credential correctness, or a live TCFS promotion. The
Codex private-state adapter produces owner-private auth and immutable SQLite
evidence plus a compatibility plan. Policy v7 retains typed auth replacement
while preserving destination SQLite exact, freezes the immutable v6
request/capacity producer closure as validator-only authority, and adds only a
CLI-inaccessible read-only diagnostic oracle for hand-built bundles. It has no
SQLite composer, reservation, publisher, installer, final verifier receipt,
combined apply, activation, or cutover. Offline receipts deliberately record
`provider_runtime_acceptance_verified=false`; working auth requires a fresh
attended provider turn. Bulkload has no destination delete or
garbage-collection command.
