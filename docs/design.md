# Bulkload product contract

Implementation lives in [tummycrypt PR #592](https://github.com/Jesssullivan/tummycrypt/pull/592).
The Python engine is retired. M0/M1 scaffolding does not complete M2.

## Completion

Sting must support daily work: authenticated agents with history, SSH, Git
commits and pushes, PR operations, editors and persistent terminal sessions.
Counts, manifests and documentation merges alone do not establish completion.

Coverage includes both hosts’ unique Git and agent state, credentials, dots,
SQLite and worktrees. Unsupported items remain outstanding with preserved
custody; never silently exclude them.

## Live union

Both hosts stay usable. Never signal sessions, require a stillness pair, or
require a writer-quiescence acknowledgement.

Git capture retains refs, objects, real stash commits including binaries and
untracked files, indexes and dirt, worktree administration and translated paths.
Import must preserve divergence and leave active HEADs, indexes and working bytes
untouched. Account credentials carry privately; platform stores may require a
format transcode. Preserve destination machine keys and Home Manager links.
Never print credential contents.

Use SQLite backup-API snapshots, never raw live WAL/SHM copies. Composition
preserves unique rows on both sides. Schema or row conflicts need retained
snapshots and explicit resolution. Rollout counts do not prove database rebuild.

## Incremental performance

R25 requires resumable parallel work without repeating completed reads or walks.
Freshness keys include source authority, device, inode, size, mtime and ctime
at nanosecond precision. They are reuse keys, not content digests. Completion
markers bind verified inputs and outputs. Changed files, replaced inodes, journal
gaps and lost source authority invalidate reuse; correctness takes precedence
over a zero-reread claim. Measure rereads, revisits, memory, wall time and
throughput on the real corpus and a small delta against rclone. Rust alone is
not performance evidence.

## Reclaim and records

Preserve unique content before deleting redundant containers. Compare content
and database rows as appropriate; names and sizes are not redundancy proof.
Hardlinks mean apparent tree size is not reclaimable space.

Current completion evidence belongs in existing Linear issues and implementation
PRs. Keep historical interviews and the week review as historical evidence.
