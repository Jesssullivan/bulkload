## What changed

- **L3: every destination syscall goes through `io::sys`.**
  - `materialize.rs` had 26 `unsafe` blocks, calling `openat`, `mkdirat`,
    `unlinkat`, `symlinkat`, `readlinkat`, `fstatat`,
    `fdopendir`/`readdir`/`closedir`, the errno slot and `geteuid`. It now
    has none.
  - The counted syncs in `counters.rs` go through sys, and its
    `F_BARRIERFSYNC` block is gone.
  - The store's `flock` goes through sys, and so do the destination staged
    writes and chmod (`transfer.rs`) and the source pack writes.
  - New sys calls: `open_dir_at`, `open_dir_path_nofollow`, `open_read_at`,
    `symlinkat` (traced), `readlinkat`, `list_dir`, `effective_uid`, and
    `flock_exclusive`/`flock_unlock`. `Stat` gains `uid`.
  - Every `unsafe` block in `io` still has one operation and a SAFETY
    comment, enforced by clippy denies.
- **Trace (R-N88).**
  - New events: `Symlink`, and `Commit { store, records }`. The stores emit
    a `Commit` when a `SQLite` commit returns: outputs, captures, directory
    created or intent, and directory complete.
  - The commit runs under the recorder's serial lock.
  - `Recorder::attach_process` records every thread without its own
    recorder, including the engine's committer and capture threads.
- **Checker (`crash_check`).**
  - No tempfile, so the R34 no-rustix wall holds. A default build exports
    nothing new.
  - Symlinks are modelled.
  - A `Commit` drains the drive holding its store (`Options::commit_drains`,
    true on Darwin with `fullfsync=ON`). Full-flush drains and device-wide
    barriers act only on their own drive.
  - `Options::ignore_foreign` drops, and counts in `Report::foreign`,
    mutations of nodes outside the image, such as a store's own files.
  - Per-mutation sent and durable points are precomputed, so a real trace
    stays fast.
  - `check_view` reads states in memory through `View`, alongside the
    materializing `check`.
- **R-N119: the fallback directory records its intent first.** An intent is
  a directory record with `(dev, ino) = (0, 0)`, committed before the
  `mkdirat` and bound to the inode afterwards.
  - A resume adopts a directory an intent owns only while it is still an
    empty 0700 directory owned by this user.
  - A failed `mkdirat` clears the intent at once.
  - `directory_after_fallback_mkdir` moved into the `scenarios!` table.
    `KNOWN_VIOLATIONS` is now the four R-N86 tests.
  - D3: the `RENAME_UNSUPPORTED_ENV` hook now runs in CI.
- **F3: per-side group limits.** `BULKLOAD_FAULT_GROUP_SOURCE` and
  `..._DESTINATION` take `<files>[:<idle_ms>]`, with `Limits::group_idle` and
  `GroupSink::SIDE`. `outputs_recorded_before_their_captures_resume` hits
  the relaxed I1 branch deterministically: at the crash, 3 outputs and
  0 captures.
- **L2:** the blanket `dead_code` allow on `io` is gone. Each unwired W4
  item (`buf`, `chunker`, `TempFile` and friends, and the sys calls only
  PR 2/3 use) carries its own allowance with a reason.
- **L4:** `tests/pr59-review` moved to `docs/evidence/pr59-review` as
  evidence.
- **D1:** the io contract table and prose are corrected, covering the
  rename fallbacks, the trace per call, and Linux never calling
  `sys::barrier` from `durable`.
- **D2:** direct sys rename-contract tests: `EINVAL` with no link, and on
  Linux `EPERM` for a directory.
- **M10 hook:** `durable::fail_dir_seals` (test-only, per thread).
- **`just fault-harness`** also runs `tests/power_loss.rs` with `io-trace`;
  the pin is in `tests/test_ci_contract.py`.

## Proofs

- **`tests/power_loss.rs`** runs `check_view` on the trace of a real
  `copy`, about 5 s in all. The invariants:
  - committed ⇒ durable;
  - no torn final names;
  - returned ⇒ complete.

  It runs in group mode and in strict mode, and covers a symlink-only copy
  and two syscall-order checks: the pack is sealed before every capture
  commit, and strict mode seals only with full flushes.
- **#59 mutants,** re-defined against the current code and each run, then
  reverted:
  - M1 (no directory seal before commit): killed by both power-loss runs and
    the materialize M10 test.
  - M3 (no pack seal before commit): killed by
    `the_source_pack_is_sealed_before_every_capture_commit`.
  - M6 (no session flush): killed by
    `a_symlink_only_copy_is_durable_once_it_returns`, on Darwin.
  - M7 (no directory seal in `finish_directories`): killed by both
    power-loss runs.
  - M8 (strict uses a barrier): killed by
    `strict_mode_seals_every_destination_node_with_a_full_flush`, on
    Darwin.
  - M10 (commit despite a failed directory seal): killed by
    `a_failed_directory_seal_commits_no_record`.
  - On Linux the per-file and directory seals are `fsync` in both modes, so
    M6 and M8 are equivalent mutants there.
