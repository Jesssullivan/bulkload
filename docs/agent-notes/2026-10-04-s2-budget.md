## What the instrument is now

- `crates/bulkload-bench/scripts/s2_budget.py` (stdlib only), trace schema
  `bulkload.s2-budget.v1`.
  - Workload v0: one step at a fixed 1 Hz cadence, each operation timed on
    its own. JSONL append + fsync; one SQLite WAL transaction
    (synchronous=FULL); `git status` + `git diff` on a 64-file fixture repo
    with one modified file; `rg` over a 256-file tree, falling back to
    `grep -r`, with the tool recorded. `step` is the sum of the four.
  - Every git child runs with `git_env`: no inherited GIT_* variable, no
    global or system config, no prompt, a ceiling at the work directory.
    The fixture commit is made with plumbing (write-tree, commit-tree,
    update-ref), which runs no hooks; `core.fsmonitor=false` keeps git from
    leaving a daemon.
  - A step that overruns skips the ticks it missed. Each missed tick is
    recorded (`missed_ticks`: due time, wait) and back-filled into every
    latency metric with its wait (coordinated omission). Sample floors count
    measured samples only.
  - Sampler: load1 at 1 Hz from `/proc/loadavg` (Linux) or
    `sysctl -n vm.loadavg` (Darwin). Power is recorded at every window
    boundary through `r23_ab.power_source`.
  - Protocol: OFF/ON/OFF/ON/OFF, 300 s windows by default. ON repeats the
    command until the window's deadline. Placeholders are `{priority}`,
    `{run}` and `{run_dir}`. The class each run reports in its `counters
    priority=` line is recorded and checked.
  - Verdict (`analyze`, a pure function; the bootstrap is seeded):
    - The first `--settle-seconds` (60) of every window are dropped.
    - d_p95 = p95(ON)/p95(OFF) − 1 for `step` and for each operation.
    - d_load1 = level(ON) − level(OFF). A window's level is its
      lag-corrected load1: the mean of its settled rows plus tau (59.5 s)
      times their slope. This inverts the kernel's 5 s EWMA to within about
      0.5 % whatever the settle. The plain mean read 0.856 X.
    - Each metric is decided on bootstrap bounds: 1000 replicates, each
      resampling whole windows within each state and then 30 s blocks
      within each drawn window.
      - PASS when the 95 % bound is within the budget.
      - FAIL when the 5 % bound is over it. For an operation the FAIL side
        uses the 5 %/4 bound (Bonferroni).
    - The latency gate is `both` by default and under evidence. It PASSes
      only when `step` and `each-op` both PASS, and FAILs only when both
      FAIL; a disagreement is INCONCLUSIVE, because the gate metric is
      unruled.
    - INCONCLUSIVE on any of:
      - a noise floor over half the budget, on any gated metric or on the
        OFF load1 levels;
      - too few samples or windows;
      - a workload or sampler error;
      - a cut-short run;
      - a failed ON run, or a priority mismatch;
      - ON busy < 80 %;
      - under evidence, a reached run cap or an R-N81 breach (below);
      - bounds that straddle a budget.
    - `raw_comparison` keeps the strict point comparison. The `gates` and
      `*_bounds` fields, `missed_ticks` and `load1_model` (what a unit add
      reads as, plain and corrected, on the trace's own windows) are
      recorded.
  - A/A mode (`--aa`): the ON windows run nothing. The result is QUIET,
    NOISY or INCONCLUSIVE, never a budget verdict.
  - Evidence only with `--evidence`, and only for the whole protocol
    (`protocol_problems`):
    - windows of at least 300 s, and at least 5 of them;
    - repeat on, and `--max-runs` at 1000 or more;
    - `--coordinator-quiet`, and not an A/A run;
    - the budgets, `gate_metric=both` and `settle_seconds=60` exactly;
    - `min_samples`, `min_window_samples` and `min_on_busy` at their
      defaults or stricter;
    - AC power and load1 < 2.5 at the start.

    `analyze` labels a trace evidence only when:
    - it was run with --evidence, and its schema is v1;
    - its recorded configuration and gate pass the same check;
    - no override differs from the recorded gate;
    - every window boundary is on AC;
    - every OFF window's load1 level is under 2.5.

    The reasons are listed in `evidence_problems`.
  - R-N11: no timeouts and no signals. The ON command is waited for until
    it exits, and an overrun extends its window and is recorded. The loops
    are bounded by the planned length plus `--max-overrun-seconds`; past
    that bound the run ends cut short and the verdict is INCONCLUSIVE.
- `crates/bulkload-bench/scripts/test_s2_budget.py`: 67 tests, about 37 s,
  including three live runs (about 17 s).
- `justfile`: a standalone `bench-s2-budget *args` recipe at the very end.

## Review round 1 (2026-10-04): fixes

Ten medium/high findings, which deduplicate to seven issues. They landed
in six signed commits (the bootstrap bounds and the gate metric share one),
in this order:

- **d79b0e5 (high): git children isolated.**
  - Before: `build_fixtures` and the 1 Hz git step inherited GIT_DIR,
    GIT_INDEX_FILE, GIT_WORK_TREE and the global config. Run from a hook,
    `rebase -x` or `bisect run`, this could replace the outer repo's main
    and index.
  - Now `git_env` drops every GIT_* variable (a superset of
    `git_carry::git_env::CLEARED`). It sets GIT_CONFIG_GLOBAL=/dev/null,
    GIT_CONFIG_NOSYSTEM=1 and GIT_TERMINAL_PROMPT=0, with a ceiling at the
    workdir.
  - Test: a decoy repo's HEAD, main and index stay byte-identical under
    hostile GIT_DIR, GIT_INDEX_FILE and GIT_WORK_TREE. The test fails
    without the fix.
- **dda26f2 (high + medium duplicate): evidence pinned to the whole
  protocol.**
  - Before: settle, the sample floors, min_on_busy, --no-repeat and
    --max-runs were free, and `analyze` overrides kept evidence=true.
  - Now `protocol_problems` is the one check for `run --evidence` and for
    `analyze`, and any differing override drops the label.
  - A run cap reached under evidence is INCONCLUSIVE.
  - Tests:
    - the reviewer's relaxed `run --evidence` line is refused on every
      relaxed value;
    - `analyze --min-on-busy 0 --settle-seconds 99` on an idle evidence
      trace prints evidence=false.
- **7ad8861 (medium ×2): lag-corrected load1.**
  - A true +2.3 now FAILs; the plain mean read about 1.96.
  - Settle 0/30/120 agree within 0.06, and every update phase within 0.02.
  - The trace records the plain attenuation (0.856 at 300/60) and the
    corrected response (about 1.0).
- **27be869 (medium ×2): R-N81 over the whole run.**
  - Under evidence, any window boundary not on AC, or any OFF window whose
    level is at or over 2.5, is INCONCLUSIVE and not evidence.
  - The level excludes bulkload's own EWMA tail.
- **4bc4f71 (medium): coordinated omission.**
  - Missed ticks are recorded per tick and back-filled with their wait.
  - The reviewer's stall pattern (6 s, one step in 22) now FAILs, at
    d_p95 over +100 %. The point estimate without the back-fill reads
    +0.9 %.
- **74ecad6 (medium ×2): bootstrap bounds and both gates.**
  - Monte Carlo, the reviewer's setup (iid lognormal, 240 settled samples
    per window, 5 windows, no drift; 200 traces per cell):

    | sigma | true effect | PASS | FAIL | INCONCLUSIVE | point estimate alone |
    |---|---|---:|---:|---:|---|
    | 0.4 | +30 % | 0.5 % | 2.0 % | 97.5 % | PASS 24.5 % |
    | 0.4 | +20 % | 16.0 % | 0.0 % | 84.0 % | FAIL 21.0 % |
    | 0.4 | 0 % | 76.5 % | 0.0 % | 23.5 % | |
    | 0.3 | +30 % | 0.5 % | 6.0 % | 93.5 % | |
    | 0.3 | 0 % | 89.5 % | 0.0 % | 10.5 % | |

  - Most INCONCLUSIVE at 0 % comes from the ruled OFF noise floor.
  - A variant with windows held fixed (blocks only) plus a hard ON-spread
    cut gave, at sigma 0.4:
    - +30 %: PASS 2.0 % and FAIL 17.0 %;
    - 0 %: PASS 70.0 %.

    The window-resampling design was kept: it never wrongly PASSed or
    FAILed more often than the variant, and it PASSes a clean run more
    often.
  - The default gate now returns INCONCLUSIVE on jsonl +60 % hidden behind
    step +15 %, where it used to PASS.

## Open

- **Gate metric ruling (OI-1003-Q34).** The default is `both`: PASS needs
  `step` and `each-op` to agree. A ruling for one of them would:
  - remove the disagreement INCONCLUSIVE;
  - remove the per-operation noise floor, which trips more often than the
    step's.
- **Bounds width.** Two ON windows make the bounds wide. A true +30 %
  reads INCONCLUSIVE far more often than FAIL. More alternations of
  ≥ 300 s, for example 9 windows (45 min), would tighten them. That is a
  protocol change for the operator.
- **Low review findings, not fixed in round 1:**
  - the noise floor counts OFF windows that follow ON windows (latency
    carryover), and no A/A baseline is required before evidence;
  - Darwin semantics: what load1 counts, fsync without fullfsync, and the
    sysctl fork every second;
  - load1's effective sample count for the floors;
  - an operator interrupt during `subprocess.run`/`Popen.wait` (stdlib
    behaviour);
  - workdir cleanup is not ownership-checked;
  - `on-runs/` copies have no space guard;
  - the selftest is not wired into `check-optional`;
  - the default workdir is unusable for root-owned parents and mount
    roots;
  - the builder's background check-fast, recorded above.
- **OI-1003-Q36.** The S2 evidence should count the SQLite wal-index
  (`-shm`) effect (#157). That counter has to come from the ON verb.
- **Linux evidence.** On Linux, `--evidence` refuses when there is no
  `Mains` power-supply class. The gated run is on neo (Darwin), so this
  does not block #165.
- **OI-1003-Q38.** Cited by the dispatch, but its text is not in this repo.
- **Linear.** No TIN-4543 comment was posted by this lane. The coordinator
