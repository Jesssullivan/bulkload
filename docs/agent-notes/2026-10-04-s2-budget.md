## What landed

- `crates/bulkload-bench/scripts/s2_budget.py` (stdlib only).
  - Workload v0: one step at a fixed 1 Hz cadence, each operation timed on
    its own. JSONL append + fsync; one SQLite WAL transaction
    (synchronous=FULL); `git status` + `git diff` on a 64-file fixture repo
    with one modified file; `rg` over a 256-file tree, falling back to
    `grep -r`, with the tool recorded. `step` is the sum of the four.
  - The fixture commit is made with plumbing (write-tree, commit-tree,
    update-ref), which runs no commit hooks, so no hook is invoked or
    bypassed. `core.fsmonitor=false` keeps git from leaving a daemon.
  - Sampler: load1 at 1 Hz from `/proc/loadavg` (Linux) or
    `sysctl -n vm.loadavg` (Darwin). Power is recorded at every window
    boundary through `r23_ab.power_source`.
  - Protocol: OFF/ON/OFF/ON/OFF, 300 s windows by default. ON repeats the
    command until the window's deadline. Placeholders are `{priority}`,
    `{run}` and `{run_dir}`. The class each run reports in its `counters
    priority=` line is recorded and checked.
  - Verdict (`analyze`, a pure function): the first `--settle-seconds`
    (default 60) of every window are dropped. Δp95 = p95(ON)/p95(OFF) − 1
    on the gate metric (`step` by default, or `each-op` for the worst
    operation). Δload1 = mean(ON) − mean(OFF), pooled.
    - INCONCLUSIVE on any of: noise floor over half the budget, too few
      samples or windows, a workload or sampler error, a cut-short run, a
      failed ON run, a priority mismatch, or ON busy < 80 %.
    - Otherwise PASS if Δp95 ≤ +25 % and Δload1 ≤ +2.0, else FAIL.
    - `raw_comparison` keeps the bare PASS or FAIL.
  - A/A mode (`--aa`): the ON windows run nothing. The result is QUIET,
    NOISY or INCONCLUSIVE, never a budget verdict.
  - Evidence only with `--evidence`. It refuses windows < 300 s, fewer than
    5 windows, non-SLO budgets or gate metric, an A/A run, a missing
    `--coordinator-quiet`, or no AC power or load1 ≥ 2.5 at the start.
    Everything else is labelled NOT EVIDENCE.
  - R-N11: no timeouts and no signals. The ON command is waited for until
    it exits, and an overrun extends its window and is recorded. The loops
    are bounded by the planned length plus `--max-overrun-seconds`; past
    that bound the run ends cut short and the verdict is INCONCLUSIVE.
- `crates/bulkload-bench/scripts/test_s2_budget.py`: 35 tests.
  - Synthetic traces: pass, p95 fail, load1 fail, inclusive bounds, too few
    samples (window, pooled and windows), the noise floor (latency and
    load1, and noise outranking a fail), the each-op gate, settle, workload
    errors, cut short, ON failure, priority mismatch, unreported priority
    under evidence, idle ON, and A/A QUIET, NOISY and INCONCLUSIVE.
  - Also: the cadence skips missed ticks, plus pattern, workdir, refusal
    and `analyze` CLI tests.
  - Three live runs (about 17 s).
    - One checks that the loops sample, that ON runs are waited for, the
      run cap, and that no thread is left behind.
    - One checks that an `--aa` run starts nothing and gives no budget
      verdict.
    - One checks that an overrunning child is waited for in full and the
      run then ends cut short.
- `justfile`: a standalone `bench-s2-budget *args` recipe at the very end.
  The check-optional block and its comment are untouched (lane A's #159
  owns them).

## Open

- **Gate metric needs a ruling.** The default is `step`: the sum of the
  four operations, i.e. one agent step's wall time. `--gate-metric each-op`
  gates on the worst single operation instead. That is stricter for the
  fsync-bound operations, and noisier.
- **load1 lag (estimator bias).**
  - load1 is a one-minute exponential average.
  - With 300 s windows and a 60 s settle, an ON window's settled mean
    reaches about 91 % of a steady add X.
  - The OFF windows that follow an ON window keep about 9 % of X as a tail,
    and two of the three OFF windows do.
  - So Δload1 ≈ 0.85 X. A steady +2.35 would read as about +2.0.
  - A simulation of the kernel's 5 s update over the protocol gives:
    - 0.856 X at 300 s windows and a 60 s settle;
    - 0.932 X at 300 s and a 120 s settle;
    - 0.973 X at 600 s and a 120 s settle.
  - Options:
    - longer windows or settle;
    - a lag-corrected estimator;
    - accept the bias, as a ruling.
- **Lane A wiring.** `test_s2_budget.py` is not in `check-optional`. The
  dispatch reserved that block for lane A's #159.
  - #159 merged to main as cb681d3 while this lane ran. This branch stays on
    4a10bb8.
  - `git merge-tree` against cb681d3 is clean: #159's justfile hunks do not
    touch the appended recipe.
  - A follow-up should add `{{ just_executable() }} bench-s2-budget

- **OI-1003-Q36.** The S2 evidence should count the SQLite wal-index
