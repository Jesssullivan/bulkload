## 2. Lever 2: the finish folded into the last group (built)

**Model first** (`docs/formal/DirectoryRecords.tla`):

- New constant `FoldFinish` (assumed only with `BatchFinish`), variable
  `owed` (an output renamed into a directory whose group has not
  committed), actions `Place(d)` and `GroupFinish(S)`. `ChildCommit` under
  `FoldFinish` commits what is owed, also inside a directory being
  finished (an earlier group still committing); `Complete` and `Exit`
  require nothing owed.
- `GroupFinish(S)`: one commit commits every owed output and completes
  every directory being finished, each `fsealed` (final mode set, then
  sealed by the group's seal after its renames).
- New invariant `CompletionAfterChildren` (a completed directory owes no
  output of its run). Mutations `fold_leaves_owed` (must violate it) and
  `fold_unsealed` (must violate `CompleteImpliesFinal`).
- Catalogue (`catalogue/Directories.dhall`): rows `MC_dir_fold` (Deep, two
  levels, two runs, one crash, no third party), `MC_dir_fold_crashes` (one
  level, three runs, two crashes, one third party), the two negative rows;
  every other pass row now names `GroupFinish` and `Place` never enabled;
  traceability row for the new invariant. 243 rendered files.

**Code** (`materialize.rs`, `transfer.rs`, `io/durable.rs`,
`transfer_store.rs`, `counters.rs`):

- `Committer::sync_last(last)` and `GroupSink::{Last, commit_last}`: the
  drain's group commits with the finish, in channel order behind every
  item; an empty group drops it.
- `Destination::fold_finish` sets every final mode (deepest first,
  identity checked as the finish does) and returns `FoldedFinish` (handles
  and keys). It refuses to fold (returns `None`) with no directory, batching
  off, more directories than a batch, a salvaged temporary to retire, or a
  final mode without this user's read, write and search bits (owner
  `0o700`; `0o300` before the review round, section 8, finding 1).
- `Inbound::fold_finish` adds the session's side: the knob, nothing refused
  so far, every `SQLite` sidecar covered by a snapshot base.
- `PublishSink::commit_with`: the finish rides only if every outcome the
  sink ever reported is OK (an earlier group's refusals are not yet in the
  receiver's stats) and, for a batched group, if each directory is
  device-sealable. The directories join `TouchedDevices`, so the group's
  seal covers them; the commit is `commit_outputs_finishing` (the
  completions deleted in the same transaction, traced as
  `DirectoryComplete` in the group's commit); `directory.before_complete`
  fires there per directory, after that seal.
- `Destination::folded_finish`: on success, counts `directories_finished`
  and the new `directories_folded`, empties the finish, removes the store's
  device from `unflushed`. `TransferStats::directories_folded`.
- Knob `BULKLOAD_DIRECTORY_FOLD=0`; test hook `set_directory_fold`.
- `r23_ab.py` records `directories_folded_total` per rep.

**The pending record cannot fold.** It must be durable before the
directory's name (R-N102, `rename_before_record`), and the name before
anything inside it is decided (`child_before_dirseal`), so it is the
session's first durable step and has no output group to ride.

## 8. Review round (2026-10-16): the fold's independent review

Seven findings against tree `f44e29d132bd4056bcfd44fc56f58c05be456d9e` (the

1. **Major, fixed: the fold's permission rule missed owner read.**
   Verified: `fold_finish` refused only `mode & 0o300 != 0o300`, then set
   every final mode before the last group committed. A finish that then
   rides no commit (the drain's group already empty, so `close_last` drops
   it; or the last group refuses) leaves `finish_directories`, or the next
   run's adoption, to open each directory `O_RDONLY | O_DIRECTORY`
   (`open_dir`, and `parent` for each component), which needs owner read.
   With `p` at `0o311`: `finish_directories` and the resume's `directory`
   both refused `Io(Some(13))` (EACCES). Fix (`materialize.rs`
   `fold_finish`): fold only when every final mode keeps owner read, write
   and search (`mode & 0o700 == 0o700`); the doc comment, `design.md` and
   `fold.rs`' comments now say read, write and search. Failing first
   (`fold-review-failing-first.log`, 0 passed, 3 failed; `fold-review-fixed.log`,
   8 passed): `materialize::fold_tests`
   `only_a_final_mode_with_owner_read_write_and_search_folds` (0700, 0755,
   0711 fold; 0311, 0333, 0355, 0555, 0600 do not),
   `a_finish_that_rode_no_group_still_finishes_a_directory_without_owner_read`,
   `a_resume_after_a_refused_last_group_adopts_a_directory_without_owner_read`.
   The tests sit at the materializer, not in `transfer::tests::fold` as the
   review proposed: a source directory without owner read cannot be walked
   by its owner, so a test that owns its source cannot copy one (the real
