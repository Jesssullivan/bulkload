## What the code does now

### #186: a refused seat is sniffed once

- `capture_file` reads the first 16 bytes ahead of the rest. A `SQLite`
  database or WAL magic refuses the seat (`SQLITE_STATE_CHANGED`, as
  before). Those bytes are then counted as the new process counter
  `source_sniff_bytes`, never as content: not in `source_bytes_read`, not in
  `read_source_file_bytes`. For a seat that is not refused they are its
  first content bytes, counted as such.
- The source ledger remembers the refusal under the seat's row key (its
  path and stat identity) in a new table `refused_seats` (kind 1 is the
  `SQLite` header). It is submitted to the ledger committer when the
  refusal is sent, needing no `Held`. It is remembered only when the seat's
  stat identity did not move across the sniff and the seat was not racy
  (the guard a capture has, #86).
- A later run looks the row key up before it opens anything
  (`remembered_refusal`): an unchanged refused seat is refused with the same
  code, 0 bytes read, counted in `transfer_refused_seats_remembered`. A seat
  whose identity moved has another key and is sniffed again.
- The refusal is reported on every run. No wire change: `WIRE_SCHEMA` stays
  v5, so a `pull`'s receiver does not see the sniff count; it is on the
  serving side's counters line.

### #187: a changed seat supersedes this store's own output

Design: the **exchange** design that `docs/formal` checks
(`MC_wp0d_exchange`), not check-then-rename. The task text sketches "publish
to a temporary, rename over"; the formal model refutes that shape
(`MC_wp0d_check_rename` fails `NoClobber`: a third party's write lands
between the check and the rename) and the README named the exchange shape
for this work, so the exchange was built.

- **Ownership** (`materialize::owned_output`). The existing output at a
  changed seat's path is this store's own when its
  `(dev, ino, size, mtime, ctime)` equals a row this store committed for
  that path under the session's output authority. The path's rows are one
  range read of the primary key: a row key starts with the encoding of
  `(authority, rel_path)` (`transfer_store::path_prefix`; a unit test holds
  that to `row_key`). No schema change to `outputs`.
- **Plan** (`plan_file`). Owned and other bytes: stage a new file beside it,
  fill it from local chunks (the old output's own, through its hints) and
  ask the source for the rest; the entry is queued as
  `Publication::Superseding`. Owned and the same bytes (a touched seat): the
  output is verified at the plan and adopted in place. Not owned: adopt if
  the bytes verify at `End`, refuse `DESTINATION_OCCUPIED` if not, as before.
  The streamed path (a seat past the source's retention budget) supersedes
  from its staged copy the same way.
- **Group commit** (`PublishSink::supersede`):
  1. seal the staged file; open the leaf and require the owned identity;
  2. one store commit (`begin_supersedes`) records every intent of the group
     in a new table `supersedes` and moves the outputs' rows into it;
  3. `RENAME_EXCHANGE` (`renameatx_np(RENAME_SWAP)` on Darwin) of the staged
     name and the leaf;
  4. check the displaced file: the same inode, size and mtime as the owned
     identity means it is the old output, which is removed; anything else is
     exchanged back, the directory sealed, the staged file removed, and the
     entry refused;
  5. the group's directory seals, then its commit: the new row, and the
     intent settled (deleted; the old rows dropped).
- **Recovery** (`Destination::settle_supersedes`, ahead of the sweep in each
  directory). An intent a crash left says what its two names may hold. Old
  output still at the leaf: its rows go back. Old output under the staged
  name: removed. Anyone else's file under the staged name: exchanged back,
  or, when the leaf no longer holds the staged file, kept where it is with
  its intent and reported in `temporaries_left`, never removed.
- **No atomic exchange** on the file system: refused
  `DESTINATION_EXCHANGE_UNSUPPORTED` before anything is staged (review fix
  1); the old output keeps its row.
- **Chunks of a superseded output** (`materialize::Displaced`). Hints name
  outputs by path. An output is entered, by the descriptor its publish
  opened, before its exchange, so a seat planned later in the session that
  still wants its chunks (a file moved out of the changed one) reads them
  there. Bounded by the descriptor budget (an eighth, at most 64).
- **Refusal codes.** New `BulkloadRefusal::DestinationOccupied`
  (`DESTINATION_OCCUPIED`) and, from the review,
  `DestinationExchangeUnsupported` (`DESTINATION_EXCHANGE_UNSUPPORTED`). Every site in `materialize.rs` and
  `transfer/unrowed.rs` raises it; `GIT_DESTINATION_OCCUPIED` is the Git
  carry's and the estate's alone. `s3_estate.py` already accepts both.
- **Counters.** `outputs_superseded`, `supersede_restored`,
  `sqlite_supersede_commits` (in `sqlite_commits_total`); from the review,
  `exchange_probes`, `transfer_refused_outputs_remembered`,
  `sqlite_refused_output_commits` (in `sqlite_commits_total`).
- **Fault points.** `supersede.after_intent`, `supersede.after_exchange`.

## Review fixes (second commit)

The review of `0293043` raised six medium findings and five low ones. All
six mediums are addressed in code; the lows are listed under Open and not
fixed. No wire change (`WIRE_SCHEMA` stays v5). Three new destination-store
tables (`owned_outputs`, `refused_outputs`; `supersedes` gained a field in
its record, new in this branch, so no stored record predates it).

1. **A destination without an atomic exchange** (finding 1).
   `Destination::exchange_supported` probes once per device and session, at
   the first changed seat found there: two empty temporaries of the store,
   exchanged and removed. Without the exchange the seat is refused
   `DESTINATION_EXCHANGE_UNSUPPORTED` as soon as its manifest shows the
   output holds other bytes (`Plan::NoExchange`): nothing is staged, no
   chunk is asked of the source. The refusal is remembered (fix 4), so a
   rerun reads 0 source bytes; the record stops answering once the file
   system has the exchange. The run that first sees the change still reads
   the changed seat once, for its manifest: a touched seat and a changed
   one cannot be told apart without it. The seat does not converge there;
   whether such destinations need a fallback is for the operator.
2. **An interrupted supersede keeps its ownership** (finding 2). The intent
   now records the staged file's size and mtime beside its inode. When the
   sweep finds exactly that file at the leaf (the exchange took effect, the
   row did not commit: a crash, or a failed group commit), it settles the
   intent with an **ownership row** for the path. `owned_output` accepts an
   ownership row as it does a reuse row, so the file is adopted from its
   capture record while its seat is unchanged and superseded when the seat
   changed again. A file written since the exchange (another size or mtime)
   gets no row. `Exchanged::Unrecorded` now leaves its intent for that
   sweep.
3. **`gate_b.py`** (finding 3; the "unavoidable" exception, another lane's
   file). `content_bytes_read` is the raw `source_bytes_read`;
   `probe_bytes`, the context field and the `sqlite_probe_bytes` meta key
   are gone, and so is the second entry of `DEVIATIONS`. `test_gate_b.py`,
   the gate (b) protocol plan and slo.md's amendment say the same.
4. **A seat standing refused is not read every run** (finding 4). The
   destination store remembers a refusal (`refused_outputs`: the entry's
   row key, a kind, the identity of the file at the path) and
   `Inbound::entry` answers `Decision::Refuse` with the same code while
   that file still has that identity. Remembered only when the capture was
   not racy and the file was settled (`verify_settled`: the same identity
   before and after it was read, not stamped within the racy window of the
   read). The pinned P21 row now asserts 0 source bytes on the unchanged
   reruns, and P74's warm run reads 0 where it read every tampered seat.
5. **A racy publish is this store's own** (finding 5). `commit_outputs`
   writes an ownership row for an output published or adopted from a racy
   capture (no reuse row, as before). A seat written again before a settled
   run adopts it is superseded. **This is a design choice the review asked
   to have ruled**: of its two options (an ownership record, or the capture
   record as proof) the ownership record was built, because it claims only
   what the store did.
6. **Two #186 mutants were green** (finding 6). New rows:
   `p23_pinned_only_refused_seats_are_answered_from_their_records` (a
   corpus of refused seats only, so the destination answers `Send`),
   `a_seat_moved_under_its_sniff_is_refused_but_not_remembered` (a test
   hook moves the seat between the sniff and the stat), and
   `p19_pinned_a_racy_refused_seat_is_sniffed_on_every_run_until_it_settles`
   (asserts `SourceSniff` on every run; in-crate tests share the process
   counters, so the counter is asserted in the serialised integration
   suite). `check_p23` also asserts the remembered count on the resume of a
   completed session.
