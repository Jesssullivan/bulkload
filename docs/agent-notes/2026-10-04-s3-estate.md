## Findings for other lanes

- **WP2 follow-ups.**
  - Grouped items take only the group base (`ExportOptions::chain` is
    ignored when `prerequisite` is set), and the snapshot commits are
    parentless. So a recaptured linked worktree re-packs its checkout.
    Hypothesis, not root-caused.
  - Linked worktrees repeat large blobs on the first pass.
  - A changed capture fetches its whole retained bundle for reuse: 179 MB
    and 13.8 s of CPU for a 5-object change.
- **WP6 PR 2.** The 16-byte sniff per refused SQLite seat per pass breaks the
  file half's "0 content bytes" clause.
- **WP0(d) / WP5.** An appended JSONL file and an edited file were read and
  then refused `GIT_DESTINATION_OCCUPIED`, so they never converge.
- **SQLite half.** snapshot has no reuse path, so S3 cannot hold for SQLite
  seats with the current verbs.
- **OI-1003-Q36.** One `-shm` was created on the first pass and touched on
  every later pass. The database and its `-wal` stayed byte-identical.
- **WP1 / S2.** `estate-capture` freshened 31, 4 and 38 object-store entries
  (estate). `git-carry-estimate` changed nothing.
- **WP3.** Bare mirrors are refused `IO (errno 2)`, so `estate-capture` exits
  `CONTRACT_SELF_INCONSISTENT`.
- **WP9 / S1.** The first-pass copy spent 664 s on 15,000 cache files and
  1,020 s on 26,478 `node_modules` files, against 9.6 s for 2.1 GB of
  `data/`.
