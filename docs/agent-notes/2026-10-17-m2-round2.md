## Build placement

- **Sting first, then honey.** Builds first ran on sting, under
  `/srv/cache/jess/cargo-target-m2r2` at `nice -n 19`. Midway, the coordinator
  moved every build, test and gate to honey, by operator ruling, so that
  sting could keep ingesting the migration.
- **What stayed on sting.** Signing, pushing, `gh` and the merge stay on
  sting, because the signing key is only there.
- **The two-host gate.** This lane's gate was a copy of
  `local-gate-merge.sh`, run from `/dev/shm`; the original was never edited.
  The copy merges main, signs and pushes on sting. It then runs `nix flake
  check`, `just check-fast` and the history secret scan on honey, on the exact
  head, after checking the tree hash. The receipt records `host honey`.
- **Gate environment notes for honey:**
  - `CARGO_HOME` is private (`~/git-build/cargo-home-m2r2`). The default
    `~/.cargo/bin` holds rustup proxies, and cargo prefers those for
    `cargo-clippy`. Concurrent lanes raced the install of toolchain 1.96.1
    there and broke a gate.
  - `TMPDIR` is on `/dev/shm`. On honey's busy XFS `/home`, the crash checker
    refused inode reuse (`every_power_loss_state_of_a_superseding_rerun...`).
  - The ssh connection bypasses the fleet ControlMaster. A mux connection
    returned 255 for a gate whose remote steps all passed. The remote now
    records its exit status, bound to the head, and the gate reads that file
    only when ssh itself returned 255.
- **The `/srv/cache/jess` quota.** It is an XFS project quota of about 360 GB
  inside a 400 GB filesystem. `df` on the directory reports the quota. Test
  fixtures under it refused `DESTINATION_SPACE_INSUFFICIENT` at the 25%
  floor: item 1's defect, met in our own build space.
