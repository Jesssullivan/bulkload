**What remains (introduced by the fix round): the per-ref CPU is
attributed to loose refs, but most of it is v1's header read-back.**

The evidence doc says the following:

- Finding 3: "per-ref CPU is loose-ref filesystem work ... the per-ref
  cost belongs to loose refs on this filesystem, not to v1 as such";
- section 2: "Ref storage is the lever. The per-ref CPU is not inherent
  to v1";
- section 4, item 5: "mostly loose-ref filesystem work";
- "What this changes": "a reftable private repository for the per-ref
  CPU".

**How it was measured.** This recheck built `q42_probes.py corpus
--shape compact` (119,761 refs) under private scratch. From a loose
private-like repository it made a bundle with `bundle create --all`:
9,544,349 B, of which 8,761,204 B is header. It then timed the agent's
reuse fetch shape: `fetch --no-tags --quiet <bundle>` with two `+src:dst`
refspecs and the agent's `-c` flags. It also timed `bundle verify` of the
same bundle. Each ran 2 times, at nice 19 and load1 27 to 41:

| Private repository | `fetch` CPU (s) | `bundle verify` CPU (s) |
|---|---|---|
| loose, 119,763 refs | 33.82, 20.53 | 8.10, 8.77 |
| reftable, 119,763 refs | 17.63, 18.35 | 9.38, 8.75 |
| empty (alternates only, no refs) | 17.57, 18.56 | 8.75, 9.38 |
| empty; the bundle lists only the 2 fetched refs (149 B header) | 0.58, 0.53 | 0.002, 0.003 |

**What it shows.**

- The reuse fetch (fit 0.212 ms per ref) and `bundle verify` (0.099 ms
  per ref) are about 60 % of the chained pass's 0.51 ms per ref. They cost
  the same with reftable refs as with no refs at all.
- They are the cost of reading back a v1 header that lists every ref, so
  they belong to v1's design. Loose refs add little to them.
- Only the ref-creating transaction (0.145 ms per ref) and the ref scans
  are loose-ref work. A reftable private repository would address about
  30 % of the per-ref CPU, not the per-ref CPU as a whole.
- This strengthens the doc's v2 point (v2 negotiates refs instead of
  listing them). The fix is to restate Finding 3, section 2's "Ref
  storage is the lever" paragraph, section 4 item 5 and the packet bullet
  to say so.
