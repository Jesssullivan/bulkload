## What changed

1. **R-N78, intent-first directories.** `Store::record_directory_intent`
   commits a `PendingDirectory::Intent { mode }` before `mkdirat`; the record
   is rebound to `Created { dev, ino, mode }` once the inode exists. On an
   existing leaf, `Destination::existing_directory` adopts it only when the
   record owns it: the bound inode, or an unbound intent whose directory is
   mode 0700, owned by the effective uid, with the same intended mode. No
   record: the old fail-closed rule (divergent mode refuses
   `GIT_DESTINATION_OCCUPIED`). If `mkdirat` meets EEXIST after the absence
   check, this invocation's intent is deleted so a resume cannot adopt a
   directory it did not create. New fault point `directory.after_intent`.
   `directory_after_mkdir` is no longer ignored and converges.
2. **R-N79, temp sweep.** Temporaries are `.bulkload-<tag>-<pid>-<n>`; the
   tag is 16 hex digits derived (blake3 `derive_key`) from the destination
   store's random authority. `receive` sweeps the root after taking the
   exclusive publisher, and `directory()` sweeps every existing carried
   directory. Removal needs: exact grammar, this store's tag, and
   `fstatat(AT_SYMLINK_NOFOLLOW)` relative to the directory fd reporting a
   regular file owned by the euid; then `unlinkat` of that name only, so a
   hard-linked published name is untouched. Left alone and reported in
   `TransferStats::temporaries_left`: another store's tag, the untagged form
   earlier engines generated, symlinks or directories with a grammar name,
   other owners, and any unlink failure other than ENOENT. Names outside the
   grammar are never considered.
3. **Walks never carry temporaries.** Chosen: exclusion on the walk, not
   documentation. Documentation cannot stop a later walk of a crashed
   destination from carrying an orphan, and an orphan holds no state of its
   own (a partial or complete copy of another output, or a second link to
   it). The exclusion matches the exact generated grammar on regular files
   only (`.bulkload-notes` is still carried) and is recorded in
   `WalkOutcome::engine_temporaries`, never silently dropped.
4. **Flaky transport test.** The injected cut is keyed to a protocol event
   (the last file's `Manifest` frame; flush marks each frame boundary)
   instead of a 700,000-byte budget. A capture commits before its file is
   offered, so every capture is durable at the cut regardless of capture
   worker order. Expectations are now reused 2, completed 1, 0 source bytes.

## Round 2: review BLOCK at 009a280 (R-N102, R-N106, R-N107)

- Rebased onto #56 at d83ecf9 (publish points split per store, the
  known-violation mechanism, the separate harness target dir).
  `directory_after_mkdir` moved into `scenarios!` and off the known-violation
  list; `sweep_root` runs after `publisher(PublisherSide::Destination)`.
- F1 (R-N102): the path-only intent state is gone. Directories are
  create-then-rename: `mkdirat` under `.bulkload-<tag>-d-<pid>-<n>`, fstat via
  `O_NOFOLLOW|O_DIRECTORY`, fsync the parent (F6), commit the record bound to
  `(dev, ino)`, then a no-replace rename (Linux `renameat2` via raw syscall
  with `RENAME_NOREPLACE`; macOS `renameatx_np` with `RENAME_EXCL`; other
  targets refuse). EEXIST refuses the leaf and removes the temporary.
  Adoption happens only on a bound inode and mode. The sweep removes only
  empty, euid-owned, tagged directory temporaries (`AT_REMOVEDIR`) and clears
  any record bound to a removed inode; a non-empty one is recorded as left.
  Fault points: `directory.after_mkdir`, `directory.after_pending_record`,
  new `directory.after_rename`.
- F2: walks exclude only the tagged grammar. Exclusions travel as a new
  `EngineTemporary` frame (protocol version 4) into
  `TransferStats::source_engine_temporaries` and the transfer report.
- F3: a record that does not own the directory at its path is cleared.
- F10: the tag is hex-encoded straight into `[u8; 16]`; pid and serial are
  canonical decimals; `clear_errno` builds on every unix target.
- The reviewer's six adversarial tests are ported to
  `crates/bulkload-agent/tests/directory_ownership.rs`, each asserting the
  hazard is absent.
- R-N107: power-loss text cites R-N88 and #49; crash children run a
  watchdog that ends the child itself with `_exit(88)` (no signals, R-N11),
  and the parent waits with stdin set to null. The asked-for ~90 s watchdog
  ended `serve_before_done` on neo (load average ~40): its child performs a
  whole copy before its point, and a full in-process copy alone took ~70 s.
  The watchdog is 4 min and the parent deadline 4.5 min, still inside the
  15-minute CI job. The coverage
  guard checks `KNOWN_VIOLATIONS` against the `#[ignore = "known violation`
  attributes in both directions and lists the four live-writer R-N86 tests.
  Publication crash receipts carry `group capture_ids=<ids> chunks=<n>`.
- Deferred to a follow-up comment on #60: F5, F7, F8, F9. For F7 (sweep read
  cost), gate the sweep on a store dirty flag and measure it in W3/W4.
- Residual: if a directory this state created is deleted by someone else
  after the rename and before `finish_directories`, and the filesystem
