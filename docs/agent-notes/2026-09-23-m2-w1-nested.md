# PR #53 nested repositories and gitlinks as typed custody (W1 nested lane)

Date: 2026-09-23. Rulings: R-N32, R-N73, R-N83, R-N89, R-N110, R-N111,
R-N114, R-N115 (Linear TIN-4540). Branch: `feat/m2-w1-nested-custody`.

## What #53 does

A foreign repository nested in a checkout (a `.git` directory, or a gitdir
pointer file into another repository's administration) and a gitlink in the
index are recorded as `NestedRepository` custody instead of refusing the
capture. The custody goes into the key only when it is non-empty, so the key
of a repository without nests is unchanged. It is written to the bundle as
`refs/carry-export/nested-repositories-v1`, beside the bundle as
`{bundle}.nested`, and as one escaped line per nest on `git-export` stderr and
in every estate receipt.

A nest is custody only when it is provably safe (R-N73, R-N83, round-3 B1).
Every one of the following refuses the capture:

- the outer repository tracks a path under the nest (checked through the
  filesystem, so case- and normalisation-folding variants count too);
- the nest's `.git` resolves to this repository;
- the nest's admin sits inside a rebuildable root that the nest is not in;
- a stash (`GIT_NEST_STASHED`);
- a commit only a detached HEAD reaches (`GIT_NEST_DETACHED_UNREACHABLE`);
- an operation in progress;
- hidden index flags, a sparse checkout, or a split index;
- a filter command in the nest's config;
- a built-in conversion attribute (`GIT_NEST_CONVERSION_ATTRIBUTE`);
- a populated submodule inside the nest (`GIT_NEST_POPULATED_SUBMODULE`);
- any staged, unstaged or untracked change, judged by a `status` whose stat
  and conversion settings are pinned.

A clean nest records its HEAD, its admin, and `unpushed`. `unpushed` is every
commit that no remote-tracking ref reaches; with no remote it is
`unpushed=all(N)`.

- **R-N89:** a clean nest's ignored files are carried as seats, exactly like
  the outer's own. Rebuildable roots inside the nest are omitted. An ignored
  inner repository refuses with `GIT_NEST_INNER_REPOSITORY`.
- **R-N114:** a nest planned as its own estate item owns its seats. The outer
  names it as `carried-by=<item>` and carries none of its seats. Overlapping
  targets are refused unless the nested source lines up with the nested
  target. `apply` restores outer items before the items nested inside them.
  Every collision is `GIT_DESTINATION_OCCUPIED`.
- **R-N110:** a gitlink that HEAD's tree also holds as a tree is carried as
  Git resolves it, and named as `gitlink-collapsed`.
- **B2 / N7:** restore keeps gitlinks staged, and creates an empty directory
  only for a directory-nest gitlink with nothing at the path.

## B4: integration with #52 (drift custody)

`origin/main` (with #52 and #56) was merged into the branch instead of
rebasing it. A merge keeps the per-finding shas cited in the three #53 mapping
comments valid, and it follows the repo's own practice for #52 and #56.

- `KeyParts` gained `nested_repositories`. It is hashed into the digest only
  when non-empty, in the same position as before, and appended to `authority()`
  under the same condition. It is compared in `drift_only`, so a nest's HEAD
  moving is authority, never drift.
- Inside the export, the nested-repository census is compared before and after
  the pass beside the nested worktrees.
- Nest seats are census rows, so they join #52's seat comparison.
- `CarriedAuthority` carries the gitlinks read with the index. `ExportOptions`
  carries `planned`.
- The estate `Completion` has #52's fields plus `nested`. The receipt reason is
  `drift=N`, `nested=N`, or both.

Tests: `a_nest_head_moving_mid_pass_refuses` and
`a_nest_head_moving_around_the_export_refuses_the_capture`.
