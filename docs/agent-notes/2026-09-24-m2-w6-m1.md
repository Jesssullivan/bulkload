## Choices made (flag in review)

- **No `--missing=allow-any` on the sender.** The plan's D2 text lists it.
  The sender uses `rev-list --missing=print` and refuses any `?` line, and
  `pack-objects` runs without `--missing`, so an object that vanishes on a
  live source refuses the segment instead of being left out of it. Either
  way PR 2's connectivity check would refuse the publish; this refuses at
  the source, before any byte moves.
- **Segment order.** Objects are assigned to segments in
  (type, basename, path) order (spike plan change 5), then each segment
  keeps rev-list order. A one-segment list is therefore exactly the single
  list, byte-identical to upload-pack's pack.
- **`pack_id`** is the BLAKE3 of the `.list` bytes, so `GitResume` names a
  self-verifying file.
