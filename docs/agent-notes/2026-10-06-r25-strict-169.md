## What changed

- **Capture record.** `transfer.rs publish` writes, before `fchmod` and before
  the group's file seal, an extended attribute on each non-racy capture's
  staged file: version, BLAKE3 of the source-side row key (the `Start`
  authority and the walked row), manifest root and size; 73 bytes. Linux
  `user.bulkload.capture`, Darwin `dev.tinyland.bulkload.capture`. The seal
  (`fsync` on Linux, `F_BARRIERFSYNC` plus the group flush on Darwin) makes it
  durable with the data. A failed write is counted
  (`transfer_capture_records_unset`), never refused.
- **Adoption** (`transfer/unrowed.rs`, `Inbound::adopt_unrowed`). An entry
  whose output exists with no matching row is adopted when the record names
  this entry's row key and the output's own bytes, chunked with FastCDC and
  hashed through `pread`, give the recorded root and size under an unchanged
  identity and the row's mode. The entry is answered `Reuse`: 0 source
  bytes, nothing on the wire. The output is queued as `Publication::Adopted`,
  so its file and directory are sealed before its row commits. Anything the
  record cannot prove takes the old manifest path, counted
  `transfer_unrowed_unproven`; a record of another row key (the seat moved)
  is not counted. New counters: `transfer_unrowed_adopted`,
  `transfer_unrowed_unproven`, `transfer_capture_records_unset`. New
  `TransferStats` fields `unrowed_adopted` and `unrowed_unproven`; the
  `copy` summary line is unchanged.
- **io layer.** `sys::set_capture_record` / `get_capture_record`, with
  platform `fsetxattr` / `fgetxattr` in `sys_linux.rs` and `sys_darwin.rs`.
  The trace has a new event `SetCaptureRecord` (class meta), and the crash
  checker models the record per file (`View::record`, materialized on
  `check`).
- **No wire change.** `WIRE_SCHEMA` stays v5; the adoption answers the
  existing `Reuse` decision.

## Model (docs/formal)

- New constant `AdoptUnrowed`, on by default (the code since #169). The
  file record gains `rec`; `RecvEntry` adopts (answering `Reuse`, queueing
  `adopt_wait`), `AnswerHeld` settles an adopted entry without a `Held`, and
  `ForeignWrite` may rewrite in place (keeping the record). Each cites its
  code site. No new action.
- `MC_r25_unrowed_bytes` now **passes** with every safety invariant plus
  `R25_StrictNoDurableReread` (446 distinct). `MC_r25_strict_deep` (main_deep
  bound, strict) passes (431,705). The old finding is kept as
  `MC_r25_unrowed_no_adopt` (fails `R25_StrictNoDurableReread`). New
  mutations `adopt_unkeyed` (fails `ReuseSound`) and `adopt_unverified`
  (fails `RecordImpliesBytes`).
- Full `just tla-check` (2026-10-06, sting, load average about 100 to 120):
  every BulkloadTransfer row matched its expectation, every mutation failed
  on its named property; `MC_nv_core` 15,834 and `MC_nv_ledger` 142,450
  unchanged. `just tla-render --check` clean.
- N-version explorer: not extended. `AdoptUnrowed` is outside its domain
  (`explorerModels`), `one` and `nvCore` keep it off, so every row in the
  explorer's domain renders and counts as before. See the open items.

## Proofs on the code

- Power-loss trace `materialize::adoption_power_loss::an_unrowed_output_is_adopted_without_source_reads`
  (`just resume-power-loss`, now 3 proofs): a crashed publish (written,
  record, mode, seal, rename, directory seal, no commit) is enumerated by the
  crash checker; each state is resumed by a real `copy` from a fresh copy of
  the source store. Surviving outputs: 0 source bytes, adopted; lost ones:
  read exactly once.
- P74 R25-STRICT-ADOPT (`transfer::tests::p74_unrowed_outputs_are_adopted_without_source_reads`,
  12 fixed seeds) plus `p74_seeds_cover_every_fate` and
  `a_racy_unrowed_output_is_read_again_and_counted`. Row appended to the
  property-test plan.
- Red on mutation (scratch mutants, reverted): adoption off fails P74, the
  power-loss proof and `a_failed_group_commit_…`; the hash check skipped
  fails P74 (a rewritten output adopted).
- Updated expectations: `a_failed_group_commit_answers_held_false_and_records_nothing`
  (the failed group's published outputs are adopted, 0 reads),
  `rows_from_before_the_racy_guard_are_read_again_once` (rewrites outputs
  without a record, as a pre-#169 store's are), and the fault harness's I3
  (published unrowed outputs cost 0 source bytes and are counted adopted).

## Open

- Every non-racy output now keeps a ~73-byte user extended attribute. It
  cannot be removed after the row commits without moving the output's
  ctime (part of its row identity). Operator review wanted.
- A file system without user extended attributes (NFS, some tmpfs before
  Linux 6.6) gets no record: those outputs keep the counted re-read. The
  power-loss proof and P74 need xattr support on `TMPDIR`; CI's runners are
  assumed to have it.
- Darwin is not compiled here (no Darwin target on sting); the `libc`
  signatures were checked against libc 0.2.184.
- `hs/Explorer.hs` does not model the capture record; extending it (and
  turning `AdoptUnrowed` on for the N-version rows) is follow-up work.
- `just formal-nv` was not re-run (host load); its domain is unchanged.
