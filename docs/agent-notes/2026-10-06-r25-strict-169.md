## What the code does now

- **Capture record.** An extended attribute on a non-racy capture's output:
  version, BLAKE3 of the walked row under a fixed domain (`record_key`; no
  store authority), manifest root and size; 73 bytes. Linux
  `user.bulkload.capture`, Darwin `dev.tinyland.bulkload.capture`. Two
  writers:
  - `Inbound::publish`, on the staged file before `fchmod` and the group's
    file seal;
  - `Inbound::adopt` (review round), on an existing output once it is
    verified against a non-racy capture's manifest (`unrowed::refresh`). An
    output that already carries exactly that record is left alone. The row
    records the identity taken after the write, which must differ from the
    verified one in ctime only.

  A failed write is counted (`transfer_capture_records_unset`), never
  refused.
- **Adoption** (`transfer/unrowed.rs`, `Inbound::adopt_unrowed`). An entry
  whose output exists with no matching row is adopted when the record names
  this entry's row and the output's own bytes, chunked with FastCDC and
  hashed through `pread`, give the recorded root and size under an unchanged
  identity and the row's mode. The entry is answered `Reuse`: 0 source
  bytes, nothing on the wire. The output is queued as `Publication::Adopted`,
  so its file and directory are sealed before its row commits.
- **Counters.** `transfer_unrowed_adopted`; `transfer_unrowed_unproven` (an
  existing output with no matching row and no record, or a record that does
  not verify); `transfer_capture_records_unset`. A record that names another
  row (the seat moved) is read again and not counted.
- **A lost source authority** (review round). The key holds no authority, so
  a recreated source store still finds its outputs' records: rowed or not,
  they are adopted with 0 source bytes.
- **No wire change.** `WIRE_SCHEMA` stays v5.

## Open

- **Ruling wanted: the N-version core of record.** `MC_nv_core` and
  `MC_nv_ledger` model the transfer before #169. The adopt rows are
  cross-checked beside them. Retiring or re-freezing `MC_nv_core`'s count
  needs a ruling (frozen name).
- **Ruling wanted: WP0(g)'s authority condition.** With an authority-free
  record key, an output that carries a record is adopted across a lost
  source authority (`MC_r25_strict_unsealed`, `MC_r25_strict_authority`
  pass). `MC_wp0g_authority` and `MC_store_root_unsealed` are kept on the
  transfer before #169 and still fail; OI-1003-Q37's condition is left as
  ratified.
- **A read-only adopted output keeps no record.** A `user.` attribute needs
  write permission on the file, so an existing output with mode 0444 that is
  adopted against a manifest gets none (counted). If that adoption's row
  then fails to commit, the seat is read once more. Changing the mode to
  write the record was rejected: a crash in between would leave a mode the
  next run refuses as `GIT_DESTINATION_OCCUPIED`.
- Every non-racy output keeps a ~73-byte user extended attribute. It cannot
  be removed after the row commits without moving the output's ctime (part
  of its row identity). Operator review wanted.
- A file system without user extended attributes (NFS, some tmpfs before
  Linux 6.6) gets no record. The power-loss proof, P74 and the review
  round's tests need xattr support on `TMPDIR`.
- Darwin is not compiled here (no Darwin target on sting); the `libc`
  signatures were checked against libc 0.2.184. `fsetxattr` on a read-only
  descriptor of an adopted output is untested there.
- The review's low findings were not fixed (lane brief): uncounted
  `Verdict::Other` fallbacks; the power-loss proof does not trace
  `Inbound::publish`; the Darwin half is uncompiled; the record is
  unauthenticated user data; the README's Results table and legend (partly
  addressed here because the rows changed: the table is now one run, and
  `pre-#169` marks the rows that keep the old transfer).
- README passages that predate #166 still call an unsealed state root "the
  code today" (the spec header and the abstraction notes). slo.md records
