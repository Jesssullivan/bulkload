# 2026-09-23 — M2 W4 io layer

The W4 io-layer lane runs in parallel with W3 (R-N90). It covers GitHub #46
and Linear TIN-4543. The branch is `feat/m2-w4-io-layer`, started from
origin/main d189969.

Rulings cited: R-N90 (start the io layer now), R-N54 (unsafe-first,
`// SAFETY:` on every block), R-N58, R-N88 (ALICE-style trace checker in
CI), R-N101 (resume the lane without shell word searches; R-N92 is
standing), R-N103 (Darwin barriers are device-wide by default), R-N69
(local builds) and R-N80 (stop on a guard refusal).

## What landed on the branch

`crates/bulkload-agent/src/io/` is `pub(crate)` and unwired. Its only
callers are its tests and the chunker micro-bench, so it has a single
`cfg_attr(not(test), allow(dead_code, reason = …))` in `lib.rs`.

- `sys_posix.rs`, `sys_darwin.rs` and `sys_linux.rs` hold the syscall
  wrappers, using only libc, with no mmap.
  - Shared calls: component-wise `openat` with `O_NOFOLLOW | O_CLOEXEC` at
    every component (so an intermediate symlink swap is refused), `fstat`,
    full-length `pread`/`pwrite` with EINTR retry, `fchmod`, `unlinkat`,
    `mkdirat`, `linkat` and `SO_SNDBUF`/`SO_RCVBUF`.
  - Darwin: `F_BARRIERFSYNC`, `F_FULLFSYNC`, `renameatx_np(RENAME_EXCL)`,
    `F_PREALLOCATE`, `F_RDADVISE` and `pthread_set_qos_class_self_np`.
  - Linux: `fdatasync`, `sync_file_range`, `renameat2(RENAME_NOREPLACE)`,
    `O_TMPFILE` plus `linkat` through `/proc/self/fd` (with a named-temp
    fallback), `fallocate(KEEP_SIZE)` and `posix_fadvise`.
  - The `barrier`, `barrier_dir`, `full_flush`, `rename_noreplace` and
    `set_socket_buffers` functions keep the W3 lane's names and shapes.
    `durable.rs` is not written here; W4 integration reconciles it onto this
    layer.
- Unsafe inventory, taken by reading the files (R-N101), as of review round
  1: `sys_posix.rs` 17 blocks, `sys_darwin.rs` 7, `sys_linux.rs` 6, and
  `buf.rs` 4 blocks plus 2 `unsafe impl` (`Send`/`Sync` for the owned slab
  block). That is 34 blocks, each with a `// SAFETY:` comment, and clippy
  now enforces one operation per block.
- `trace.rs` adds the `io-trace` feature. Every mutating wrapper (create,
  write, sync, rename, link, unlink, mkdir, fchmod) records an event with the
  node identity, offset, length, bytes, BLAKE3 digest and sync kind. With the
  feature off, the recording sites are removed by `cfg`.
- `crash_check.rs` is test-only. It enumerates crash states from a trace
  under a documented persistence model (Pillai et al., OSDI '14; Apple
  `fcntl(2)` and the "Reducing disk writes" guidance). It materializes each
  state into a temporary directory and runs an invariant on it.
  - The enumeration is exhaustive up to 12 optional mutations per crash
    point. Above that it tries the prefix, required, drop-one and keep-one
    states, and logs every bounded point with its skipped-subset count.
  - Under R-N103 the default barrier scope is device-wide. The per-object
    scope remains available as a strict option.
- `buf.rs` is a pool of 4 MiB slabs, 16 KiB aligned and zero-initialized.
  `take` blocks for backpressure, and a slab returns itself to the pool when
  dropped.
- `chunker.rs` fuses slice-FastCDC v2020 (16/64/256 KiB, the same
  parameters as `hash.rs`) with per-chunk BLAKE3. Large inputs are cut in
  speculative 4 MiB segments that a sequential stitcher joins, and a
  `cdc_redo_bytes` counter records the bytes cut twice.
- `justfile`: `rust-check` now also runs clippy and the io tests with
  `--features io-trace`. A new `bench-io-chunker` recipe runs the
  micro-bench.

## Proofs

- **Crash checker, hand-written traces:**
  - The correct publish protocol (write temp, sync, rename, dir sync)
    passes with every durable sync pair and under both barrier scopes.
  - Without the file sync it fails: the name can survive with the wrong
    bytes.
  - Without the dir sync it fails: the protocol returns but the data is not
    durable.
  - W3's barrier-only group protocol passes under the default device-wide
    model and fails under the strict per-object model (R-N103).
  - Also covered: torn writes, mkdir dependency, mode/link/unlink rules, the
    bounded-point log, and refusal of an untraced event.
- **Crash checker, traces recorded from the real wrappers (`io-trace`):**
  - The same pass and fail results for the named-temp and `TempFile`
    publish paths.
  - The group protocol passes under the default model. Under the strict
    model it fails on Darwin and passes on Linux, where `barrier` is
    `fdatasync`.
  - On Linux, a test on tmpfs runs the `O_TMPFILE` plus `linkat` path.
- **Proptests:**
  - The buffer pool matches its model over 256 cases: capacity, no
    overlap, alignment, zeroed fresh slabs, and write isolation.
  - The chunker is bit-identical to `fastcdc::v2020::FastCDC` plus blake3,
    sequential and segmented (serial and parallel), over 48 random cases.
  - Explicit segment-edge tests cover segments that start on true cuts,
    ±1 byte around a cut, segments smaller than a chunk, input lengths
    around segment multiples, and all-zero input.
- **Miri: not run.** nixpkgs ships no Miri, its rustc is stable, and no
  nightly is installed. No `miri-buf` recipe was added and no rust-overlay
  (single audited input). The `buf` tests are written to be Miri-friendly
  for when a nightly is sanctioned.
- **Local gates on the nixpkgs toolchain (rustc 1.96.1, Darwin):**
  - `fmt --check` passes.
  - `clippy -D warnings` is clean for the workspace, and for the agent with
    `io-trace`.
  - `test --workspace --locked` passes: 109 agent tests.
  - The io tests pass with `io-trace`: 50 after review round 1.
- **Linux cfg paths:** clippy was checked on x86_64 and aarch64 Linux
  through a scratch mirror crate (not committed). They run in CI.

## Chunker micro-bench — taken under load

Taken on 2026-09-23 on this lane's host (Mac17,5, AC power; `hw.perflevel0`
= 2, `hw.perflevel1` = 4; 6 rayon threads) with a release build. The input
was 256 MiB of random data, run 5 times per arm.

**The load average was 21.82 / 28.23 / 29.40.** These rows are not gate
evidence. The low-load rerun (`just bench-io-chunker`) is pending the
R-N91 quiet window.

| arm | median MB/s | reps MB/s |
|---|---|---|
| current `hash.rs` path (chunk boundaries + per-chunk BLAKE3 + whole-file BLAKE3) | 179.4 | 208.7, 180.0, 90.0, 159.4, 179.4 |
| current `hash.rs` path, chunks only | 134.9 | 134.9, 135.1, 130.4, 130.0, 182.1 |
| fused sequential | 160.6 | 146.8, 160.6, 207.9, 233.4, 139.7 |
| fused segmented, serial | 159.1 | 133.2, 194.8, 200.9, 115.8, 159.1 |
| fused segmented, parallel | 616.6 | 602.6, 637.2, 759.8, 522.9, 616.6 |

- `cdc_redo_bytes` was 3,741,064 of 268,435,456 bytes (1.4 %) on both
  segmented arms.
- The rep spread is wider than the gap between the single-thread arms.
  The current path even measures faster with an extra whole-file pass than
  without it. The only conclusion these rows support is that the parallel
  segmented arm is about 3.4× faster than the current path.
- W2's low-load M0 run measured about 1.4 GB/s for CDC alone per P-core.

**Fixed in this round:**
- **#1:**
  - The Linux `O_TMPFILE` tests print `RAN …`. They fail if `/dev/shm` is
    unusable, unless `BULKLOAD_ALLOW_NO_DEV_SHM` is set.
  - `rust-check` now runs the `io-trace` proofs before the workspace
    tests, so a v3 flake cannot hide them.
- **#2, mutants M3, M4, M5:** each is pinned by a toy trace.
  - `a_full_flush_drains_only_what_was_sent` (M3).
  - `a_device_barrier_orders_only_sent_mutations` (M4).
  - `syncing_the_file_after_the_rename_is_too_late` (M5).
- **#13, mutant M9:** `a_new_directory_is_a_dependency_of_its_entries`
  now asserts on the persisted event set.
- **Mutant M11:** the bounded test also requires that drop-one states
  appear.
- **Mutation check:** all five mutants were re-run locally and are now
  killed, each by its intended test.
- **#3:** traced calls hold a reentrant per-recorder serial lock from before
  the syscall until the event is appended. Covered by
  `concurrent_traced_writes_replay_to_the_file_on_disk`, which races two
  threads writing into one file.
- **#4:** `open_tmpfile` probes `/proc/self/fd` once. If it is unreachable,
  staging uses a named temp. The `AT_EMPTY_PATH` fallback is removed.
- **#5:** a trace that reuses a node identity for a Create or Mkdir is
  refused (probe P1 ported: `inode_reuse_in_a_trace_is_refused`).
- **#6:** `Report::passed` is false for a bounded run unless
  `Options::accept_bounded` is set. `Report::exhaustive()` was added.
  Probe P2 is ported into the bounded test.
- **#7:** `pwrite_all` traces the prefix the kernel accepted before a
  failure.
- **#8:** `take_timeout` uses `checked_add`. An unrepresentable deadline
  waits forever (`an_unrepresentable_timeout_waits_forever_without_overflow`).
- **#10, part:** `TempFile` keeps a duplicate of its directory
  descriptor. `publish(self, name)` consumes it and, on failure, hands the
  staged file back in `PublishError`.
- **#12:** Create and Mkdir events record the effective mode from `fstat`
  (`create_and_mkdir_events_record_the_effective_mode`).
- **#14:** the `dep_graph` FORBIDDEN list gains `nix`, `rustix`, `memmap2`
  and `io-uring`. tempfile's rustix is dev-only; the normal graph has none.
- **#15:** `io` denies `clippy::undocumented_unsafe_blocks` and
  `clippy::multiple_unsafe_ops_per_block`. The Darwin `pthread_self` call
  is split into its own block.
- **Unsafe count after this round:** `sys_posix` 17, `sys_darwin` 7,
