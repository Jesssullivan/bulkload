## What was done

1. **Design note first** (`fa25c6d`):
   `docs/plans/2026-10-05-v1-header.md`. A ref table commit plus one tip ref
   per distinct object; exact expansion at apply; old-format compatibility;
   R25/S3; restore exactness; the L1 and chain/base custody interaction
   (`GitCarry.tla` needs no change: it abstracts header and pack content);
   the typed size refusal and write-time checks.
2. **Implementation** (`b62604d`), `crates/bulkload-agent/src/git_carry/`:
   - `ref_table.rs` (new): `encode`/`write` (one `fast-import` into the
     write store, then one `update-ref` transaction of D tip refs) and
     `expand` (strict: tips equal the table's objects, metadata-only header
     beside a table, sorted unique lines, canonical namespaces).
   - `git_carry.rs`: `capture_refs` writes the table; `import_verified`
     fetches one refspec per distinct object on stdin, then expands.
   - `shared.rs`: `HEADER_CAP`; every reader refuses `GIT_INVENTORY_OVER_CAP`
     over it; `write_full` sums its header from the private refs before
     `bundle create`; `write_excluding_tip_trees` (grouped items and chained
     links) measures its header before the walk; `prerequisite_commits` is
     one `cat-file --batch-check`, skips the base's table, and refuses a
     head the item cannot hold `GIT_INVENTORY_MISSING_PREREQUISITE`.
   - `chain.rs` (`advertised` typed), `shallow.rs` (manifest cap at write
     and read).
   - `bulkload-proto` `refusal.rs`: `GitInventoryOverCap` /
     `GIT_INVENTORY_OVER_CAP` (variant, code, `CODES`, the uniqueness test
     row); `docs/design.md` rows.
   - WP1 hardening is unchanged: every child comes from `git`/`git_writer`;
     the table's objects go to #172's write store (`git_writer`).
3. **Tests** (`refs_scale_tests.rs`, new; fixtures
   `crates/bulkload-agent/tests/fixtures/v1-old-format/`):
   - REFS-SCALE, generated (proptest, `prop_config(4)`): loose and packed
     refs, packed refs shadowed loose, annotated tags, a tag of a tag, refs
     to a tree and a blob, chained symrefs, `refs/worktree/*`, a stash,
     canonical namespaces copying the native refs, SHA-1 or SHA-256. Exact

   - REFS-SCALE fixed row: **138,416 refs**, 726 distinct objects: header

   - SHA-256 row in both formats; 65,779-ref old-format row (header

## Open

- **Operator ruling: the persisted format.** Every new v1 capture is
  written with a ref table; captures written before still restore (tests
  above). Ratify, or rule a threshold (old format below N refs). The
  implementation is uniform pending the ruling.
- **All-distinct inventories.** The header is 111 B per distinct object
  (159 B SHA-256); the cap falls at about 151,000 distinct objects (about
  105,000 SHA-256), refused typed. Anchoring commit tips under octopus
  anchor commits would make it O(1), but `source_held_tips` would then
  need the prior's pack, not its header.
- **Smaller table** (about 1.3 MB per chained pass at 119,761 refs): object
  indexes into the tip list instead of object names.
- **Old-format apply at 119,761 refs costs 284 s of CPU** (flatten's loose
  refs, and fetch matching 1,032 refspecs against 119,768 advertised
  refs). Only captures written before this change pay it.

  relative corpus path resolves its scratch paths twice under `git -C` and
  refuses `GIT_INVENTORY_MALFORMED`. Both seen while measuring; candidates
  for issues.
