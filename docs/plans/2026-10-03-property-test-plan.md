**Why this matters (OI-1003-Q13).** Running neo→sting should feel like any other sync. That only holds if S2, S3 and S5 are stated as universal properties, not shown on a few hand-picked fixtures. Everything else is consolidation: fewer test bodies, one oracle per claim, and a fixed-seed corpus in CI.

## 1. Property catalogue

Conventions:
- **CI** uses a fixed RNG seed (`ProptestConfig { rng_seed: RngSeed::Fixed(..), cases: N_ci, failure_persistence: None }`) through one shared `test_support::prop_config(n_ci)` helper. Each CI run is then the same bounded corpus.
- **Deep tier** (`BULKLOAD_PROPTEST_DEEP=1`, `just props-deep`; on demand, never a PR gate): the helper keeps the same fixed seed and sets `cases = N_ci × 20`. **The helper's seed is fixed in both tiers (OI-1003-Q78, 2026-10-06)**; before that ruling the deep tier drew random seeds. A deep run is the PR corpus's own stream drawn further, so a deep failure of a helper-routed property reproduces with the same command. The guard below holds this in the PR gate: the helper's tier is a parameter (`prop_config_for(cases, deep)`), the guard asks for both tiers and requires `Fixed(CI_SEED)` in each, and the helper's source may name a seed on one line only. **One property is not on the helper yet**, so "one fixed seed everywhere" is not yet true of the tree: `refusal_taxonomy` has its own fixed seed (`0x5733_7265_6675_7365`) and does not multiply its cases in the deep tier. The other exemption, the random-seed `git_carry_v2::random_dags_equal_upload_pack`, left with its file in Q42 L5 (#189), so no property in the tree draws a random seed.
- **Guard (2026-10-06).** `crates/bulkload-agent/tests/prop_seed_guard.rs` (in `cargo test --workspace`, so in check-fast) scans every workspace `.rs` file one line at a time. It is a text check, not a parse. The only accepted config is the helper call as the whole expression on one line: `#![proptest_config(test_support::prop_config(<cases>))]` or `TestRunner::new(test_support::prop_config(<cases>))`, with an optional `crate::`/`self::`/`super::`, or bare `prop_config(..)` under the plain import `use ..::test_support::prop_config;`. A struct update over the helper, a wrapper around it and a trailing comment that spells it are refused. It also fails on `ProptestConfig`; on `test_runner::Config`, a braced or glob `test_runner` import and a `test_runner as` rename; on the bare word `Config` in a file that uses proptest; on `RngSeed` / `rng_seed`; on `FileFailurePersistence` / `failure_persistence`; on a local `fn prop_config` or a rename onto the helper's name; on any other `TestRunner` use except the plain import; and on a `proptest!` block with no config. It errs towards refusing valid code in another layout, and it does not see through a macro or alias that hides every one of those spellings. An integration test reaches the helper by compiling `src/test_support.rs` as a `#[path = "../src/test_support.rs"] mod test_support;` module; a mirrored copy of the helper is refused. Its exemption list only shrinks. It landed with two entries: `tests/git_carry_v2.rs` (unseeded) and `tests/refusal_taxonomy.rs` (its own fixed seed). The first left with carry_v2 (WP2 PR 3, 2026-10-05; the ceilings fell from 2 files and 11 findings to 1 and 7); the second migrates onto the helper next.
- A **finite matrix** (a small product of enums) is **enumerated exhaustively**, not sampled.
- Named reviewer regressions become rows in a `PINNED` table beside the property.
